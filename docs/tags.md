## Uniqueness

The tag's _uniqueness_ describes how many tag applications there can be and what the circumstances are.

* `Uniqueness.Single` means that the tag can only be applied at most **a single time** across the whole database.
* `Uniqueness.Limited` has the same effect for unit tags as `Uniqueness.Single`. For tags with associated values, this
  option ensures that each value possible is only applied at most _once_ per database.
* `Uniqueness.OncePerObject` means that the tag can only be applied at most **once per object**. If the tag has as
  associated value, then this option ensures that there is one value at max associated with the object.
* `Uniqueness.Many` means that the tag can be applied multiple times per object. This means that there is an array of
  values of a tag on an object. For unit tags, this option has the same effect as `Uniqueness.OncePerObject`.

This constraint directly maps to the SQLite uniqueness constraints of tables.

* For a unit tag, the table schema is always `(id INTEGER...)`. `Uniqueness.Single` means that this table is
  obsolete and for `Uniqueness.OncePerObject` the uniqueness constraint of the primary key `id` is sufficient.
* For a tag that has an associated value the default schema is `(id INTEGER..., value ANY)`:
  * `Uniqueness.Single` is implemented using the same global table as the unit tag does for this option.
  * `Uniqueness.Limited` is implemented using a primary key on `value`.
  * `Uniqueness.OncePerObject` is implemented using a primary key on `id`.
  * `Uniqueness.Many` is implemented using a combined primary key on `id` and `value`.
